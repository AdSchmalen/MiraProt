# MiraProt Support

MiraProt is open-source research software maintained on a best-effort basis.

## Before asking for help

Please first check:

- `README.md`
- the files in `Documentation/`
- `GUIDE_PORTABLE_USER.md` for portable installations
- existing GitHub Issues

## Software problems

For reproducible software problems, open a **Bug report** on GitHub.

Please include the information requested by the issue form, especially the MiraProt version, operating system, installation mode, affected module, and steps needed to reproduce the problem.

## Feature requests

Use the **Feature request** form for suggestions about new features, workflows, interfaces, or analysis capabilities.

Requests that may change scientific or statistical behavior should clearly state the intended methodological change.

## Scope of support

Reasonable support topics include:

- installation problems
- reproducible software errors
- unexpected application behavior
- documentation problems
- portability problems
- questions about how a documented MiraProt feature is intended to work

The following are generally outside the scope of project support:

- analysis of individual research datasets
- interpretation of biological results
- statistical consulting
- design of research studies
- troubleshooting unrelated R, operating-system, or network administration problems
- guaranteed response times or individual user support

## Data privacy

Do not post unpublished, confidential, patient-identifying, personally identifying, proprietary, or otherwise sensitive data in public GitHub Issues.

Use synthetic or properly anonymized examples whenever possible.

## Security issues

Do not report suspected security vulnerabilities in a public Issue. Follow the instructions in `SECURITY.md` and use GitHub's private vulnerability reporting feature.
